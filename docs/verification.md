## Checks and observed limitations

- Python 3.13.18 and SQLite 3.54.1 on macOS arm64 were used. FastAPI 0.162.0, Starlette 1.10.0, pytest 9.2.0 and Playwright 1.64.1 are recorded with the complete lock and execution metadata.
- TestClient emits one Starlette deprecation warning about its httpx integration. It is not hidden. Independent process HTTP and Chromium tests also run, so the system boundary is not verified only through TestClient.
- The first browser check reported the deliberate self-approval 403 as a console resource error. The test now explicitly requires that exact response/error at that step, then requires no subsequent browser errors; this did not change the application's authorisation rule.
- The first dependency audit found three advisory entries in setuptools 80.9.0 (including a duplicate advisory). The build dependency was upgraded to 84.1.0 and the scan rerun. The checked-in JSON is the actual final scan. The local application is not a public package to which the advisory service can assign a vulnerability record.
- A test-fixture SQL insert initially had the wrong column count. It was corrected to exercise the intended deferred foreign-key failure. A migration-initialisation connection was changed to explicit closing. These were fixed before the final suite.
- Default sandbox permissions blocked binding a localhost test port. Real HTTP/browser tests were then run with explicitly approved local-process permissions. This was an execution restriction, not a test pass.
- Browser captures show genuine executed synthetic state. Random dispatch/receipt UUIDs change per run. Tokens are not displayed in them. No screenshot, throughput benchmark, coverage percentage, external audit or CI badge is fabricated.
- No real company infrastructure, data, vendor credentials, cloud service or deployment is used. Private strategy research was not copied. No other repositories were modified.
